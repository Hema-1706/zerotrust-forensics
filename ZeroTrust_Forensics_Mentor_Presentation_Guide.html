1. How to Present to Your Mentor / Evaluators

The 3-Minute Presentation Pitch:

"During cybercrime investigations, traditional case management tools fail to detect if an evidence file on disk was modified, and record custody transfers as unverified text edits. ZeroTrust Forensics enforces continuous verification: every evidence upload gets an intake SHA-256 fingerprint, custody transfers require dual Ed25519 digital signatures from both parties, and every event is stored in an append-only hash-linked audit ledger with real-time tamper alerts."

Key Talking Points (Why Our Solution Over Standard Blockchain):

  • Direct File Byte Verification: Blockchains cannot store multi-gigabyte forensic files (RAM dumps, disk images) and only store text. Our system verifies physical disk file bytes against SHA-256 intake digests.
  • Dual-Party Ed25519 Approval: Unilateral transfers are rejected. Both Sender and Intended Receiver must sign the payload independently before custody shifts.
  • Zero Gas Fees & Sub-second Verification: Delivers the exact cryptographic immutability of a blockchain hash chain ($\text{Prev\_Hash} \to \text{Curr\_Hash}$) with zero transaction cost or P2P node latency.
  • Live Anomaly Simulator: Built-in controls allow evaluators to flip 1 byte on disk live and watch the system catch the violation instantly.

2. Module-by-Module Explanation & Functionality

Module Name What It Does Cryptographic / Security Mechanism
1. Authentication & RBAC Controls user access for Admin, Investigator, Lab Analyst, and Auditor. Node scrypt password hashing + unique salts + timingSafeEqual comparison. Server-enforced session cookies.
2. Cases Directory Organizes investigation dockets with classification levels. Classifications (SECRET, CONFIDENTIAL, RESTRICTED, UNCLASSIFIED) with evidence linkage.
3. Evidence Vault Uploads, fingerprints, and re-checks digital evidence integrity. Genuine SHA-256 intake hashing, physical file byte re-verification, AES-256-GCM encrypted notes, and Evidence Receipts.
4. Custody Transfers Handles chain of custody transfers between personnel. Asymmetric Ed25519 digital keypairs. Transfer requires dual independent signatures verified via crypto.verify.
5. Audit Ledger Chain Records immutable event log history. Append-only SHA-256 hash chain ($H_N = \text{SHA-256}(N \parallel \dots \parallel H_{N-1})$). Includes chain recalculation & repair tools.
6. Security Alerts Surfaces real-time security violations and anomaly reports. Automated trigger on file tamper, forged signature, or audit break with severity levels (CRITICAL, HIGH, MEDIUM, LOW).

3. Step-by-Step Live Demonstration Checklist (How to Check the Working)

Step 1: Launch & Access App
Start server via npm run start -- -p 3001 and open http://localhost:3001.
Step 2: Sign In as Investigator
Click "Investigator" on the Quick Role Switcher Bar to sign in as Det. Marcus Vance.
Step 3: Register New Evidence
Navigate to Evidence Vault → Click Upload & Fingerprint Evidence. Select a sample file. Observe the 64-character SHA-256 hash computed directly off the file bytes.
Step 4: Run SHA-256 Verification
Click Verify Hash. Confirm the green status: INTACT.
Step 5: Test Live File Tampering Detection
Click Simulate Tamper (alters 1 byte on disk) → Click Verify Hash. Watch the status turn RED TAMPERED and trigger a CRITICAL Security Alert!
Step 6: Restore File Bytes
Click Restore File → Click Verify Hash to confirm return to green INTACT.
Step 7: Initiate Custody Transfer (Ed25519 Sign)
Navigate to Custody Transfers → Click Initiate Custody Transfer to Elena Rostova (Lab Analyst). Observe the Sender's Ed25519 digital signature.
Step 8: Accept Transfer as Receiver
Switch role to Lab Analyst → Click Sign & Accept Custody. Observe dual-signature cryptographic verification and custodian update.
Step 9: Inspect & Verify Audit Chain
Navigate to Audit Ledger Chain → Click Verify Audit Ledger Chain to verify sequence hashes from genesis block to current head.
